# ProxyBot v1.2 Phase 3 — AI Integration & Developer Experience

## Problem Statement

ProxyBot v1.1 shipped core features (GraphQL decoder, Prometheus metrics) but lacks two critical capabilities that competitors have already shipped:

1. **MCP Server integration** — anything-analyzer (2.3k stars in 4 months) demonstrated that exposing proxy capabilities as MCP tools creates a new AI-agent-native usage pattern. ProxyBot's Gen tab exists in isolation; it cannot be used by Claude Desktop, Cursor, or Windsurf without MCP Server.

2. **AI analysis quality** — Gen tab's LLM inference processes all requests including noise (static assets, CDN, third-party SDKs), increasing token cost ~60% and producing lower-quality API specs. anything-analyzer's two-phase pipeline (noise filter → deep analysis) solves this.

3. **Filter usability** — ProxyBot's Filter DSL requires complex AND/OR/NOT expressions. proxelar's column-scoped filter (`method:POST host:api status:2*`) is 3-5x faster for common queries and has a gentler learning curve.

## Solution

Three coordinated improvements to make ProxyBot AI-agent-native and more ergonomic:

1. **MCP Server** — Expose ProxyBot's capture, classify, rules, and replay capabilities as MCP tools consumable by any MCP-compatible AI agent
2. **AI Two-Phase Analysis** — Add a noise-filtering phase that removes third-party/static/duplicate requests before running Gen tab inference
3. **Column-Scoped Filter DSL** — Add intuitive `column:value` syntax alongside the existing AND/OR/NOT DSL

## User Stories

### MCP Server
1. As an AI agent developer, I want to call `proxybot.capture_traffic()` from Claude Desktop, so I can automatically analyze mobile app traffic without leaving my chat window
2. As an AI agent developer, I want to call `proxybot.classify_app(host)` from Cursor, so I can programmatically tag traffic by app name
3. As an AI agent developer, I want to call `proxybot.get_rules()` and `proxybot.add_rule()` from Windsurf, so I can configure routing rules through natural language
4. As an AI agent developer, I want to call `proxybot.replay_requests(session_id)` from Claude Code, so I can replay captured traffic in CI without a GUI
5. As a security researcher, I want ProxyBot to appear as an MCP server in Claude Desktop's available tools, so I can audit mobile app traffic through conversation
6. As a developer using Copilot, I want ProxyBot's traffic data accessible as MCP tools, so I can build custom analysis workflows
7. As an API designer, I want `proxybot.analyze_api(session_id)` to return an OpenAPI spec, so I can generate documentation from live traffic

### AI Two-Phase Analysis
8. As a mobile developer, I want Gen tab to automatically ignore third-party SDK requests (analytics, crash reporting), so my API spec only documents my own endpoints
9. As a mobile developer, I want Gen tab to deduplicate parameterised requests (e.g. `GET /users/{id}` once, not 50 times for 50 user IDs), so the generated spec is clean
10. As a mobile developer, I want Gen tab to filter out CDN and static asset requests, so the spec focuses on actual API calls
11. As a mobile developer, I want Gen tab to estimate token cost before running inference, so I can budget my API key usage
12. As a team lead, I want phase 1 to produce a "noise report" showing what was filtered, so I can understand what traffic exists in the capture
13. As an API consumer, I want a streaming progress indicator during analysis, so I know the operation is still running for large captures

### Column-Scoped Filter DSL
14. As a mobile developer, I want `method:POST host:api` to filter to just POST requests to the api subdomain, so I can find relevant requests faster
15. As a security researcher, I want `status:4*` to show all 4xx responses, so I can quickly spot authentication or permission errors
16. As a QA engineer, I want `duration:slow` to show requests above the 95th percentile latency, so I can identify performance bottlenecks
17. As a mobile developer, I want `type:json` to filter responses with JSON content-type, so I can focus on structured API responses
18. As an API designer, I want `size:1KB` to show responses larger than 1KB, so I can spot unexpectedly large payloads
19. As a mobile developer, I want plain text search alongside column filters, so I can combine `host:example.com password` to find password-related requests to a specific host
20. As a backend developer, I want existing AND/OR/NOT filter expressions to continue working, so I don't have to rewrite existing filter shortcuts

### QR Code CA Distribution
21. As an iOS developer, I want to scan a QR code from my Mac to install the CA certificate, so I can set up HTTPS interception without AirDrop or email
22. As an Android developer, I want a QR code that links to a download URL for the CA certificate, so I can install it on any device by scanning once
23. As a team lead, I want the CA QR code to be accessible from the Tauri GUI's Certs tab, so new team members can set up quickly

### proxybot-core Crate
24. As a Rust library author, I want to include `proxybot-core` as a dependency, so I can embed ProxyBot's MITM engine in other Rust tools
25. As an open source contributor, I want a clean API surface (no GUI/Tauri dependency), so I can extend ProxyBot without understanding the full desktop app
26. As a security researcher, I want to use proxybot-core as a library in my own Rust project, so I can build custom MITM tools for specific targets

### Project File Management
27. As a QA engineer, I want to save a capture session to a `.proxybot` file, so I can archive and share test sessions with the team
28. As a security researcher, I want to load a previous capture session, so I can compare traffic across different app versions
29. As a mobile developer, I want per-session workspaces with isolated rules and devices, so I can test different app configurations simultaneously
30. As a team lead, I want to export a workspace as a tarball, so I can share a full capture environment with a colleague

## Implementation Decisions

### Module Structure

```
src-tauri/src/
├── mcp/                      # NEW: MCP Server module
│   ├── mod.rs                # Module exports, Tauri command registration
│   ├── server.rs             # MCP protocol implementation (stdio transport)
│   ├── tools.rs              # Tool definitions matching MCP schema
│   └── handlers.rs           # Handler functions per tool
├── ai_pipeline/              # NEW: Two-phase analysis pipeline
│   ├── mod.rs                # Module exports
│   ├── filter.rs             # Phase 1: noise detection and removal
│   ├── analyzer.rs           # Phase 2: LLM-based API analysis
│   └── cost.rs               # Token estimation and budget enforcement
├── filter/                   # EXISTING: Enhanced DSL
│   └── parser.rs             # Add column:value parsing alongside existing DSL
```

### Key Interfaces

**MCP Server**
- Transport: stdio (Claude Desktop compatible)
- Protocol: MCP 1.0 (Model Context Protocol)
- Tools: `capture_traffic`, `classify_app`, `get_rules`, `add_rule`, `replay_requests`, `analyze_api`, `get_session`
- Each tool maps to existing Tauri commands; MCP is a thin stdio wrapper

**AI Pipeline**
- `NoiseFilter::filter(requests: Vec<InterceptedRequest>) -> FilterResult` — removes noise, returns (candidates, noise_report)
- `ApiAnalyzer::analyze(candidates: Vec<InterceptedRequest>) -> ApiSpec` — runs LLM inference on cleaned request set
- `CostEstimator::estimate(candidates: Vec<InterceptedRequest>) -> CostEstimate` — pre-flight token budget
- `StreamingAnalyzer::analyze_streaming(...)` — yields incremental results via `Box<dyn Iterator>`

**Column-Scoped Filter**
- Extend existing `FilterExpr` enum: add `ColumnMatch { column: FilterColumn, value: String }` variant
- `FilterColumn`: method, host, status, type, size, duration, path, scheme
- Parse `column:value` as `ColumnMatch`; existing AND/OR/NOT continue to work unchanged
- Evaluation: `ColumnMatch::matches(&InterceptedRequest) -> bool`

### QR Code
- Generate QR code containing the CA PEM as a data URL or local download link
- Use `tiny_qr` or `qrcode` crate (no external dependency)
- Serve via embedded HTTP server on localhost for download (avoids file sharing complexity)

### proxybot-core Crate
- New `proxybot-core/` directory at crate root alongside `src-tauri/`
- Publish to crates.io as `proxybot-core`
- Core exports: `ProxyEngine`, `CertManager`, `RulesEngine`, `DnsState` — no Tauri, no GUI
- Re-export key types from `src-tauri/src/` via a workspace Cargo.toml

### Project File Management
- `Workspace` struct: `{ name, db_path, rules, devices, created_at }`
- Format: `.proxybot` = gzip-compressed tar archive containing SQLite + YAML + metadata
- Export: `workspace::export(path, &Workspace)`; Import: `workspace::import(path) -> Workspace`

## Testing Decisions

- **MCP Server**: Integration test — spawn `proxybot mcp` subprocess, send MCP JSON-RPC over stdio, verify tool responses
- **AI Pipeline filter**: Unit test — pass a fixture of 50 requests (mixed noise + real API), assert noise removed and real API candidates retained
- **AI Pipeline cost**: Unit test — estimate cost for 1000-request capture, assert within 10% of actual token usage
- **Column filter parser**: Unit test — parse `method:POST host:api status:2*`, verify `FilterExpr::ColumnMatch` produced; assert backward compat with existing AND/OR/NOT
- **Workspace export/import**: Integration test — create workspace, export to temp file, import, assert equal db content

## Out of Scope

- Anything beyond stdio transport for MCP (no StreamableHTTP for v1.2 — stdio is sufficient for Claude Desktop)
- HTTP/3 or QUIC support (P3, research-only)
- Transport-layer TCP/UDP proxy (P3)
- Native Windows GUI (Phase 2 only)
- Mobile app (iOS/Android) for MCP tools

## Further Notes

All three features are independently deployable. MCP Server and AI Pipeline share no code paths. Column-scoped filter is purely additive to the existing DSL (backward-compatible).

Priority ordering for implementation: MCP Server → AI Two-Phase → Column Filter → QR Code → Workspace → proxybot-core
